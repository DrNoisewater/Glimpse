Glimpse audio crackle fix — FIFINE AM8 / Windows WASAPI

This source ZIP extends the prior build-fixed source package. No precompiled Windows EXE
is included. Use build-windows.cmd on Windows 10/11 with Visual Studio/CMake.

Changed:
- src/audio_policy.hpp: smooth PCM mixer peak protection (soft limiter), packet frame
  continuity for small Windows capture timestamp jitter, mixer overload diagnostics.
- src/audio.cpp + src/audio.hpp: preserve audio on bad QPC timestamps when possible;
  correct small packet alignment jitter; count repairs; preserve counters after toggles.
- src/capture.cpp: 300-ms audio staging headroom to avoid writing MP4 audio ahead
  of delayed microphone packets; write additional diagnostic fields in metrics.
- tests/audio_tests.cpp: soft limiting, packet continuity and gap regression tests.
- README.md: USB microphone checks and how to interpret capture metrics.

Checks completed here:
- Linux CMake configuration and GCC build of portable tests: passed.
- CTest: audio_tests passed; policy_tests passed.
- Windows-specific recorder and AAC encoder are not runnable/tested in this container.

Before testing Glimpse:
1. Choose FIFINE AM8 as the Windows default recording device.
2. Record a short microphone-only clip, then another in mic+system mode.
3. If possible use a 48 kHz microphone format in Windows sound device properties.
4. Keep the Glimpse microphone level modest if the voice sounds overloaded.
5. Find the video and its .mp4.metrics.txt sidecar. Examine
   audio_dropped_frames, audio_discontinuities, audio_bad_timestamps,
   audio_timestamp_corrections, and audio_mixed_overload_frames.
6. If crackling persists, provide the metrics.txt and a 5–10 second recorded clip.

No hardware fault is established by this patch; OBS clean audio suggests the
application audio path is a better starting point than replacing the microphone.
